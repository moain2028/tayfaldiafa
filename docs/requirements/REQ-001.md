# ذاكرة المشروع داخل المستودع

## القصة
بصفتي وكيلًا يدخل المشروع في بيئة جديدة أريد أن أعرف الحالة والقرارات والحقائق من المستودع وحده حتى أكمل العمل بلا تخمين.

## المتطلبات (صيغة EARS)
- REQ-001.1 — The repository shall provide a single entry file (`AGENTS.md`) listing what to read, in order.
- REQ-001.2 — The repository shall record every business fact with its source and date, and every open question as unknown, in `docs/FACTS.md`.
- REQ-001.3 — When a work session ends, the agent shall update `STATUS.md` and add an entry under `docs/sessions/`.
- REQ-001.4 — If a Markdown link inside the repository points to a missing file, then `scripts/check-memory.mjs` shall exit with a non-zero code.
- REQ-001.5 — If `STATUS.md` is newer than the latest session entry, or dated in the future, then `scripts/check-memory.mjs` shall exit with a non-zero code.
- REQ-001.6 — While `docs/research/standards.md` is older than 90 days, `scripts/check-memory.mjs` shall print a warning.

## معايير القبول
- [x] `node scripts/check-memory.mjs` ينجح على نسخة مستنسخة حديثًا من GitHub. (الدليل في [سجل الجلسة](../sessions/2026-11-21.md))
- [x] الفحص يفشل عند كسر رابط عمدًا. (نفس السجل)
- [ ] وكيل آخر في بيئة جديدة يكمل مهمة من المستودع وحده. **لم يُختبر** — يُختبر في أول جلسة قادمة.

## خارج النطاق
صدق محتوى الملفات: الفحص الآلي يتحقق من البنية والروابط والتواريخ، ولا يستطيع أن يعرف إن كان ما كُتب صحيحًا.
