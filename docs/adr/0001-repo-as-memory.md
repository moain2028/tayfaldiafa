# 0001 — المستودع هو ذاكرة المشروع

## السياق والمشكلة
المالك يريد أن يدخل أي وكيل جديد، في بيئة جديدة، إلى المستودع فيكمل العمل بلا فقدان سياق وبلا تخمين.
الوكيل لا يحمل ذاكرة بين الجلسات، فكل ما لا يُكتب في المستودع يضيع.
المالك أعطى `moain2026/cortex-memory` مرجعًا للطريقة.

## الخيارات
1. نسخ هيكل توثيق cortex-memory كما هو (AGENTS / STATUS / LESSONS / CHANGELOG / ADR / requirements / design / runbooks / postmortems).
2. نفس الهيكل مع إضافات تسد ما ينقصه لمشروع موقع تجاري.
3. استخدام مكتبة CORTEX نفسها (`cortex/core2.py`) كذاكرة للوكيل.

## القرار
الخيار 2.

الخيار 3 مرفوض الآن: ملف STATUS في ذلك المستودع يقول إنها نموذج أولي على بيانات اصطناعية، وربطها بالوكلاء (M5) لم يُنفَّذ.

الإضافات على الهيكل الأصلي، وسبب كل واحدة:
| الإضافة | تسد ماذا |
|---|---|
| `docs/FACTS.md` بقسمي «مؤكد» و«مجهول» | أخطر تخمين في موقع تجاري هو اختراع اسم أو هاتف أو مدينة أو رقم. الملف يجعل المجهول مكتوبًا بدل أن يُملأ بالتخمين |
| `docs/sessions/` سجل لكل جلسة | STATUS يقول «أين نحن»؛ السجل يقول «كيف وصلنا، وما الذي فُحص فعلًا، وما الذي لم يُحفظ» |
| `docs/research/standards.md` بتاريخ تحقق ومصدر لكل بند | «أحدث المعايير» تتقادم. الوكيل يعرف عمر كل معلومة ومتى يعيد فحصها بدل الاعتماد على ذاكرته |
| `docs/research/inherited-lessons.md` | للمالك مواقع ضيافة سابقة موثقة الأخطاء؛ لا ندفع ثمنها مرتين |
| `scripts/check-memory.mjs` | القواعد المكتوبة تُنسى. الفحص الآلي يكشف رابطًا مكسورًا أو حالة لم تُحدَّث |
| `GEMINI.md` بجانب `CLAUDE.md` | المالك يستخدم أكثر من وكيل؛ كلها تشير إلى AGENTS.md |

## العواقب
- ✔ نقطة دخول واحدة وترتيب قراءة ثابت لأي وكيل.
- ✔ المجهول ظاهر ومعدود.
- ✘ كلفة: تحديث 3–4 ملفات في نهاية كل جلسة. إن أُهملت صارت الذاكرة كاذبة، وهذا أسوأ من غيابها. الفحص الآلي يكشف بعض الإهمال (تاريخ الحالة، الروابط) لا كله: لا يستطيع أن يعرف إن كان محتوى STATUS صادقًا.
- ✘ الملفات تكبر مع الوقت. حين يتجاوز STATUS أو سجل الجلسات حدًّا مريحًا للقراءة تُنقل المدخلات القديمة إلى أرشيف.
